# Phase 1D Implementation: Scanning Options Testing & Baseline Framework

**Created**: 2025-11-08
**Duration**: 3-4 working days
**Objective**: Create comprehensive framework to test and compare different scanning configurations with hardware-specific baselines

## Overview

Phase 1D creates a systematic framework to test different parser configurations (Marker with/without LLM, with/without force OCR, Docling with/without TableFormer, etc.) and track their performance to make data-driven routing decisions.

**Rationale**: Published benchmarks don't reflect performance on our specific hardware and dataset. We need empirical data to optimize the Intelligent OCR Router in Phase 2.

class ParserConfigurationTester:

    def run_with_metrics(

## CLI Commands

### 1. benchmark-configs
**Purpose**: Run configuration test suite

```bash
# Run all configurations in suite
poetry run data-ingestor benchmark-configs \
  --suite data/benchmarks/config_suites/comprehensive_suite.yaml \
  --documents data/benchmarks/DocLayNet/sample_100 \
  --output results/config_baseline_20251108.json

# Run specific parser configurations
poetry run data-ingestor benchmark-configs \
  --parsers marker,docling \
  --documents data/benchmarks/DocLayNet/sample_100 \
  --output results/marker_docling_test.json

# With progress tracking
poetry run data-ingestor benchmark-configs \
  --suite comprehensive_suite.yaml \
  --documents sample_100 \
  --output results/baseline.json \
  --progress \
  --workers 4
```

### 2. baseline-create
**Purpose**: Create versioned baseline from results

```bash
# Create baseline from test results
poetry run data-ingestor baseline-create \
  --name "phase1d_baseline" \
  --results results/config_baseline_20251108.json \
  --description "Initial Phase 1D baseline with Marker/Docling configurations"

# Auto-capture hardware and dataset fingerprints
poetry run data-ingestor baseline-create \
  --name "phase1d_baseline" \
  --results results/config_baseline_20251108.json \
  --auto-fingerprint
```

### 3. baseline-compare
**Purpose**: Compare baselines or configurations

```bash
# Compare two baselines
poetry run data-ingestor baseline-compare \
  --baseline1 phase1d_baseline:v1 \
  --baseline2 phase1d_baseline:v2 \
  --output comparison_report.html

# Compare against latest baseline
poetry run data-ingestor baseline-compare \
  --results new_results.json \
  --baseline phase1d_baseline:latest \
  --output comparison.html

# Statistical analysis
poetry run data-ingestor baseline-compare \
  --baseline1 baseline1 \
  --baseline2 baseline2 \
  --statistical-tests \
  --significance-level 0.05
```

### 4. compare-configs
**Purpose**: Analyze and visualize configuration trade-offs

```bash
# Generate comparison report with visualizations
poetry run data-ingestor compare-configs \
  --results results/config_baseline_20251108.json \
  --output-format html \
  --output comparison_report.html

# Focus on specific metrics
poetry run data-ingestor compare-configs \
  --results results.json \
  --metrics speed,accuracy,cost \
  --output report.html

# Get configuration recommendations
poetry run data-ingestor compare-configs \
  --results results.json \
  --recommend \
  --optimization-target balanced \
  --document-type scanned
```

## Example Use Cases

### Use Case 1: Identify Best Marker Configuration
**Scenario**: Test Marker with different LLM/OCR settings on scanned documents

```bash
# Run configuration suite
poetry run data-ingestor benchmark-configs \
  --suite marker_variants.yaml \
  --documents scanned_docs/ \
  --output marker_comparison.json

# Analyze results
poetry run data-ingestor compare-configs \
  --results marker_comparison.json \
  --optimization-target accuracy \
  --document-type scanned \
  --output marker_analysis.html
```

**Expected Outcome**: Identify that Marker with `force_ocr=True` gives 15% better accuracy on scanned docs at 2x cost

### Use Case 2: GPU Acceleration Benefits
**Scenario**: Compare Docling GPU vs CPU performance

```bash

poetry run data-ingestor benchmark-configs \
  --suite docling_gpu_cpu.yaml \
  --documents table_heavy_pdfs/ \
  --output docling_gpu_test.json

# Compare results

  --results docling_gpu_test.json \
  --metrics speed,gpu_utilization \
  --output docling_gpu_analysis.html
```

**Expected Outcome**: Document 3-4x speedup with GPU, justify GPU infrastructure

### Use Case 3: Baseline Tracking Over Time
**Scenario**: Track performance across code changes

```bash
# Create initial baseline
poetry run data-ingestor baseline-create \
  --name "v1.0_baseline" \
  --results v1_results.json

# After code changes, compare
poetry run data-ingestor baseline-compare \
  --results v1.1_results.json \
  --baseline v1.0_baseline:latest \
  --statistical-tests \
  --output regression_check.html
```

**Expected Outcome**: Detect any performance regressions before deployment
