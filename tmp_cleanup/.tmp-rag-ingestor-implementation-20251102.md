# RAG Data Ingestor - Implementation Reference

**Date**: 2025-11-02
**Status**: Phase 1 - Foundation
**Purpose**: Preserve context across conversation compactions

## Project Overview

Building a comprehensive RAG data ingestion pipeline to replace unstructured.io (cost too high).
Focus on open-source alternatives like Marker (small revenue exception).

### Target Formats
1. PDF (Priority 1) - Scientific papers, scanned docs, tables, formulas
2. DOCX (Priority 2) - Office documents with formatting
3. Websites (Priority 1) - JavaScript rendering, clean extraction
4. Video (Priority 2) - Transcription, multi-language support
5. Audio (Phase 2) - Similar to video

### Core Technologies Decided
- **PDF**: Marker (primary), Docling (tables), GROBID (academic), PyMuPDF (fallback)
- **DOCX**: docx2python (primary), python-docx (fallback)
- **Web**: Crawl4AI (primary), Playwright (JS rendering), BeautifulSoup (parsing)
- **Video**: Faster-Whisper (primary), Whisper (high-accuracy fallback)
- **Framework**: FastAPI + Celery + Redis
- **Database**: PostgreSQL (metadata), Redis (cache), MongoDB (optional document store)

## Architecture Components

### 1. Document Router
- Format detection via python-magic
- Parser selection logic
- Fallback chain management

### 2. Parser Registry
- Multiple parsers per format with priority ordering
- Health checking and fallback
- Configuration-driven selection

### 3. Processing Engine
- Celery workers for parallel processing
- Redis task queue
- Resource management (CPU/GPU)
- Error recovery and retry logic

### 4. Chunking Module
- Element-based chunking (recommended)
- Token-based with overlap (fallback)
- Table integrity preservation
- Context window management

### 5. Quality Assessor
- Extraction completeness scoring
- Structure preservation metrics
- Automatic fallback triggering
- Human review flagging

### 6. Storage Manager
- PostgreSQL for metadata
- File system/S3 for documents
- Vector store integration point
- Versioning and deduplication
